What is a Replay Attack?

A replay attack occurs when a transaction signed for one BSC network is maliciously or accidentally rebroadcast on another BSC network. This can happen when transactions lack proper chainId protection.

Why is this dangerous?

Without chainId protection, a transaction signed on one BSC network (e.g., BSC Testnet) could be replayed on another BSC network (e.g., BSC Mainnet), potentially causing:

  • Unauthorized transfers: Funds moved without user consent
  • Double spending: Same transaction executed twice
  • Network confusion: Transactions on wrong networks
  • Security breaches: Exploitation of unprotected transactions

How ChainId Protection Works

Modern BSC transactions include a chainId field that binds the transaction to a specific network. This prevents:

  • Replaying transactions across different BSC networks
  • Accidental execution on wrong BSC networks
  • Cross-network transaction confusion

Supported Networks

  • BSC Mainnet (ChainId: 56)
  • BSC Testnet (ChainId: 97)
